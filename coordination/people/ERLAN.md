# Ерлан — качество, README и демонстрация

Задача [T-05](../tasks/T-05.md), ветка `test/T-05-erlan-evaluation`.
Ресурс: один Pro 5×. Твои пути: evals/, docs/evaluation/, README.md, карточка T-05.
Сроки: [PLAN.md](../../PLAN.md). Интерфейс: [contracts.md](../../docs/contracts.md).

## Порядок работы

1. Изучи публичный runner/scorer и контракт. Начни со stub и template,
   пока Нурсултан и Бауыржан пишут реализацию.
2. Проверяй исходный список Agent.act: evaluator может обрезать лишние кампании,
   поэтому один успешный local_eval ещё не доказывает корректность ответа.
3. Проверь ресурсы вместе с пилотами, фильтры, повторные контакты, пропуски,
   отрицательные эффекты и остановку по времени. Не извлекай скрытую модель.
4. Два разных публичных ответа пилота должны приводить к обоснованному изменению
   оценок/решения. Бессмысленный вызов run_pilot не засчитывай как использование данных.
5. Сравни baseline и интегрированный hash на одинаковых seed; фиксируй все результаты.
   На дополнительном наборе seed проверь, не исчезает ли улучшение.
6. Проверь два запуска make_submission в своей локальной копии, сравни CSV.
   Не перезаписывай финальный submission Нурсултана.
7. Напиши README с проверенным запуском, архитектурой, результатами и ограничениями;
   подготовь короткое демо и передай bug reports до заморозки 16:45.

Каждый баг: commit, команда, seed/вход, ожидаемое и фактическое поведение,
минимальный воспроизводимый пример. Исправление agent.py делает Нурсултан,
strategy/ — Бауыржан. В отчёт попадают агрегаты, не строки клиентов и не ключи.

## Модели

**GPT-6 Sol medium** — разработка проверок, README и разбор обычных логов.
**Sol high** — трудная регрессия/проверка инвариантов. **Luna medium** — короткая
сводка уже проверенных результатов и форматирование. Итоговые числа брать из
реальных запусков, не генерировать моделью. Если модель недоступна, доступный Sol.
API/GPU для этой задачи не нужны. Береги остаток лимита для финальной проверки.
