# Beeline Tariff Marketing Campaign Agent

Проект команды SapaTech для HackAlem AI 2026, трек 04 «Телекоммуникации».
Официальный кейс — план кампаний смены тарифа для синтетической аудитории из
23 441 абонента. Цель — максимизировать прирост ARPU после стоимости контактов.
Это не реальные клиенты или показатели Beeline.

## Состояние и состав

Проверенная версия команды — commit [`4272a07`](https://github.com/BAITC-Hacks/hack-6e2e5c8b-sapatech/tree/4272a0787248de1481fb6b45dfcbdecee1568ae4)
в `main`; `submission.csv` этой версии уже находится в Git. Ветка T-09 содержит
документацию и инструменты независимой проверки, но не заменяет исходную
стратегию без отдельного решения координатора. Публикация Git-коммита сама
по себе не означает сдачу на платформе.

- `agent.py` реализует официальный `Agent.act(env)`, публичные пилоты,
  учёт времени и ресурсов.
- `strategy/` строит кандидатов по профилю и истории смены тарифов, выбирает
  пилоты, обновляет оценку по ответам и составляет портфель кампаний.
- `evals/` проверяет исходный ответ до official sanitizer, влияние обратной
  связи, сравнение на одинаковых seed и повторяемость CSV.
- `scripts/prepare_case.py` устанавливает из официального ZIP только 13
  разрешённых файлов; при различающемся существующем файле прекращает работу.

Официальный `make_submission.py` запускает агента на mock seed 42 и создаёт
`submission.csv`. Агент работает локально: внешние API, GPU, NVIDIA Brev и
ключи для исполнения не требуются. UI и сервер не входят в путь судейства.

## Чистый запуск из `main` (macOS/Linux)

Нужны Git, Python **не ниже 3.11**, доступ к частному командному репозиторию и
официальный `beeline_case_participants.zip`, выданный организаторами. Архив,
исходные CSV и ключи не находятся в Git и не должны коммититься. Используйте
**новый клон**, чтобы проверка не затронула уже сохранённый командой CSV.
Проверьте версию `python3` перед запуском; приведённый путь к ZIP замените
своим. Команды выполняются по порядку в обычной POSIX-оболочке:

```sh
git clone https://github.com/BAITC-Hacks/hack-6e2e5c8b-sapatech.git beeline-check
cd beeline-check
git switch main
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/prepare_case.py '/path/to/beeline_case_participants.zip'
.venv/bin/python -m unittest scripts.test_agent strategy.tests.test_core evals.test_contract_checks -v
.venv/bin/python local_eval.py
.venv/bin/python evals/check_agent.py --agent agent.py --package . --feedback-check
.venv/bin/python make_submission.py
shasum -a 256 submission.csv
```

`requirements.txt` фиксирует `numpy==2.3.5` и `pandas==3.0.1`.
`scripts/prepare_case.py` оставляет официальные файлы неизменными и не
перезаписывает отличающиеся локальные файлы. Если архив уже распакован, нужен
именно его исходный ZIP от организаторов для этой последовательности; не
выдавайте заново собранный архив за официальный. Установка пишет файлы в
новый клон, где они игнорируются Git. `make_submission.py` переписывает CSV
только в этом одноразовом клоне; для проверенной версии ожидается Git/LF SHA-256
`305c7d41394309b68287c035f2c89fcd08875dede274df40f08de9241e65e46a`.
На Windows байтовый хеш может отличаться из-за CRLF; логические строки
сравниваются после нормализации переводов строк.

Чистая установка точных зависимостей и официальный запуск в новом macOS venv
с Python 3.13.7 зафиксированы в [аудите T-07](docs/planning/next_round_2026_09_23/project_actual_audit_2026_09_23_ru.md).
Аудит использовал `uv pip install`. Ерлан отдельно проверил показанный
`python -m venv` + `pip install -r requirements.txt` на macOS/Python 3.12.14:
установились pandas 3.0.1 и numpy 2.3.5; в изолированном снимке main прошли
35/35 тестов, `local_eval.py` и feedback-check, `make_submission.py` создал
CSV, побайтно равный сохранённому файлу (`305c7d4…e65e46a`). Для этого
локального прогона 13 исходных файлов были взяты из ранее распакованного
пакета и временно перепакованы в ZIP: это проверяет установщик и полный
запуск, но **не** заменяет сверку с исходным архивом организатора и не является
проверкой буквальной команды `git clone`. Командный Windows-запуск на Python
3.12.14 и уже установленных зависимостях опубликован в
[RECEIPTS](coordination/RECEIPTS.md); свежая установка Windows venv/pip
этим свидетельством не подтверждена. На машине Ерлана PowerShell не запускался.

## Как читать результат

Локальный evaluator использует синтетические скрытые эффекты, отличающиеся от
судейства. По опубликованному [аудиту T-07](docs/planning/next_round_2026_09_23/project_actual_audit_2026_09_23_ru.md)
для commit `4272a07` завершились 100/100 mock seed 0–99 без raw-ошибок:
75 прибыльных, 25 убыточных; средний net **+315 844.67**, худший
**−585 009.70**. Официальный template на тех же seed имел 0/100 прибыльных и
средний net **−533 649.30**, но он намеренно слаб. Seed 42 текущей стратегии:
net **+327 917.04**, 20 пилотов, 10 финальных кампаний, 15 000 контактов и
99 998 расходов. Это не прогноз hidden judge и не обещание прибыли.

Ограничения кейса: 1–10 финальных кампаний, до 5 000 абонентов на кампанию,
15 000 контактов и 100 000 денежных единиц **вместе с пилотами**; до 20
пилотов с запросом 10–200 абонентов. Фактический охват пилота после
ограничений может быть меньше 10. Каналы: `push`, `sms`, `digital_ads`, `call`.
Один абонент даёт только лучший эффект, но повторные контакты расходуют
ресурсы. Отдельный риск — перенос измеренного эффекта бесплатного `push`
на платные каналы; 25 убыточных seed показывают, что устойчивость прибыли
не доказана. Подробности — в [аудите](docs/planning/next_round_2026_09_23/project_actual_audit_2026_09_23_ru.md)
и [отчёте риска](strategy/reports/B1-002-r1.md).

## Демонстрация и дальнейшие изменения

[Пятиминутный сценарий](docs/evaluation/demo.md): задача → профиль/история →
пилоты и обратная связь → итоговые кампании/ресурсы → mock-результат и
оговорки. Факт публичного показа не подтверждён. Текущая версия в `main`
остаётся baseline следующего этапа. Экспериментальная стратегия может заменить
её только после независимого сравнения двух ревизий в отдельных процессах и
копиях пакета по заранее объявленным критериям; старый compare_agents для
этого без доработки непригоден из-за риска общего импорта `strategy`.
Общий CSV, интеграцию и отправку на платформе выполняет Нурсултан после
отдельного разрешения оператора.
