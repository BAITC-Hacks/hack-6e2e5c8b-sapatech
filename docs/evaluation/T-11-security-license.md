## Рекомендация по публикации

**Сохранять репозиторий закрытым.** Улучшенная стратегия готова к командному
ревью; положительные mock-результаты не дают разрешения на публичный релиз.

1. `HACKATHON.md:301` требует ограничить доступ командой и организаторами.
   Строки 134–135 требуют согласования распространения исходных данных и
   запрещают публичную загрузку архива/сырых данных. Это действующие локальные
   инструкции; отдельное разрешение организаторов в рассмотренных материалах
   не найдено.
2. В проекте нет `LICENSE`, `LICENCE`, `COPYING` или `NOTICE`. Отсутствие
   лицензии не доказывает, что автор не может публиковать собственный код,
   но не предоставляет пользователям полноценного open-source разрешения.
   Для такого релиза нужно согласовать лицензию с правообладателями вкладов
   участников. [Разъяснение GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
3. В именах файлов официального ZIP нет лицензии/условий распространения;
   целевой поиск в `PARTICIPANT_GUIDE.md` не выявил разрешения на публикацию.
   Это не исключает отдельного соглашения с организаторами. Данные и их Python
   kit не становятся свободно распространяемыми из-за отсутствия `LICENSE`.
4. Публикация собственного Python-кода с `requirements.txt` и распространение
   готового окружения/бинарников — разные составы поставки. Упаковывать весь
   рабочий каталог, `jobs/`, официальный kit или runtime для публичного релиза
   нельзя считать проверенным вариантом. Текущий `.gitignore` их исключает.

Есть воспроизводимый пробел фиксации зависимостей: `requirements.txt` закрепляет
только NumPy/pandas, но не транзитивные версии и не хеши дистрибутивов. Уже сейчас
чистая установка выбирает другую tzdata. Перед воспроизводимой поставкой
рекомендуется отдельный lock-файл с полным набором версий и хешами для целевой
платформы. Это не обнаруженная CVE и не причина менять проверенную стратегию.

`pip-audit` проверяет известные записи для Python-пакетов, а не доказывает
отсутствие неизвестных дефектов или вредоносного кода.
[Область проверки инструмента](https://github.com/pypa/pip-audit#security-model).

Дополнительно установлен Python 3.12.14 — security-релиз от 12 августа 2026;
версия сверена с [официальным объявлением](https://blog.python.org/2026/08/python-31214-31116-31021/).
NumPy сообщает о встроенном OpenBLAS 0.3.30. На просмотренной
[странице безопасности OpenBLAS](https://github.com/OpenMathLib/OpenBLAS/security)
нет опубликованных advisories. Полный аудит CPython, Windows, компилятора,
всех нативных DLL и цепочки сборки этим не выполнен; нулевой результат pip-audit
не распространяется автоматически на эти компоненты.

## Лицензии и notices

Основные лицензии зависимостей допускают использование/распространение при
соблюдении условий. Для копий библиотек нужно сохранять применимые copyright,
license и disclaimer; BSD не разрешает подразумевать endorsement авторов.
Проверены локальные license-файлы точных установленных дистрибутивов и
первичные источники:

- [NumPy 2.3.5](https://github.com/numpy/numpy/blob/v2.3.5/LICENSE.txt).
- [pandas 3.0.1](https://github.com/pandas-dev/pandas/blob/v3.0.1/LICENSE).
- [python-dateutil 2.9.0.post0](https://github.com/dateutil/dateutil/blob/2.9.0.post0/LICENSE).
- [six 1.17.0](https://github.com/benjaminp/six/blob/1.17.0/LICENSE).
- [tzdata](https://github.com/python/tzdata/blob/2026.3/LICENSE) и
  [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0).

Установленный Windows wheel NumPy также содержит notices OpenBLAS (BSD-3-Clause),
LAPACK (BSD-3-Clause-Open-MPI), других MIT/Zlib/BSD частей и GCC runtime
`GPL-3.0-or-later WITH GCC-exception-3.1`. Исключение позволяет квалифицирующемуся
независимому коду использовать runtime без автоматического перевода собственного
кода под GPL; оно не отменяет условия распространения самого runtime.
[Текст исключения](https://www.gnu.org/licenses/gcc-exception-3.1.en.html),
[FAQ GNU](https://www.gnu.org/licenses/gcc-exception-3.1-faq.html.en).
При бинарной поставке сохранять полные notices конкретных wheels, а не только
краткую строку «NumPy — BSD». Полная цепочка прав команды и отдельные соглашения
организаторов не проверены; общую юридическую очистку этот аудит не подтверждает.

## Использует ли скрипт AI при запуске

**Вызова LLM, нейросетевого inference или внешнего AI API нет.**

Фактический путь: `Agent.act` → локальная CSV-история → `build_candidates` →
`choose_pilot` → публичный `env.run_pilot` → обновление статистической оценки →
`select_campaigns`. Код использует стандартную библиотеку, NumPy и pandas.
`predicted_arpu` поступает готовым столбцом входных данных; эта программа сама
не вычисляет его обученной моделью. Пустой OPENAI_API_KEY в `.env.example` —
задел на возможную интеграцию, не признак действующего вызова.

Это адаптивный статистический агент, решения которого меняет обратная связь,
но называть его LLM-агентом было бы неверно. Источник или метод подготовки
`predicted_arpu` вне репозитория не установлен этим аудитом.

Дополнительный seed-42 запуск с Python audit-hook, запрещающим сетевые и
subprocess-события во время `act`, завершился в режиме `strategy`, без ошибок,
с 20 пилотами и 7 кампаниями; событий сети/дочерних процессов — 0.
Hook не является OS sandbox и не доказывает поведение произвольного native-кода.
