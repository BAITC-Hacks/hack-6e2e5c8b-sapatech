## Result

Revision 2 продолжает начатый [ER-001-r1](ER-001-r1.md), не повторяя уже
сделанную работу. Исправлена ложная ошибка при фактическом пилоте 1–9 человек:
запрос `run_pilot` (10–200) захватывается отдельно при доступности, а публичный
`pilot_history` проверяется как фактическое исполнение (1–200). Если запрос
недоступен, его число не выводится из результата. Сохраняются проверки
фактических контактов, цены канала, остатков, совокупных лимитов и запрета
`actual > requested`. Никакой код агента, стратегии или scorer не менялся.

Два одинаковых seed42 CSV в отдельных временных копиях совпали побайтово на
macOS. Mac CSV: 474 байта, 11 LF, SHA-256
`305c7d41394309b68287c035f2c89fcd08875dede274df40f08de9241e65e46a`.
После **только** LF→CRLF он занимает 485 байт, а SHA-256 становится
`bdcc64500857306de26e459acd4bc266da0e9a696b2a1ab3c416163517a7c91c` —
точно опубликованный Нурсултаном Windows SHA-256. Его revision 2 независимо
подтверждает обратную CRLF→LF проверку Windows-файла. Таким образом,
различие этих двух файлов — окончания строк; порядок 10 кампаний и 7 колонок
сохраняется. Логический SHA-256 macOS CSV с сохранением порядка строк/колонок:
`cca88bdea9668f55b534c3ddd380862e79b66c3b5291eca5036b4e07940f61ee`.
Официальный `make_submission.py` не менялся. `check_submission.py`
теперь выводит raw/LF/CRLF и логический hash без строк клиентских данных.

README обновлён для интегрированного агента: выделены реально исполненные
macOS-команды и отдельно отмечен непроверенный PowerShell-пример, который
сначала делает временную копию официального пакета. Windows-исполнение
остаётся задачей Нурсултана.
