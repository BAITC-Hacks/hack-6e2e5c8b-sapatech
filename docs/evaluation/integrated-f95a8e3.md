копия с `agent.py` и `strategy/` из указанного коммита. Команды выполнялись
из ветки T-05 с Python, pandas и numpy:

```text
python -m unittest evals.test_contract_checks -v
python evals/check_agent.py --agent <staged>/agent.py --package <staged> --seed 42
python evals/check_agent.py --agent <staged>/agent.py --package <staged> --feedback-check
python evals/compare_agents.py --baseline-agent <package>/agent_template.py --candidate-agent <staged>/agent.py --package <staged> --runs 10
```

raw-ошибки baseline template** на seed 3 (ноль финальных кампаний). У кандидата
нет raw-ошибок. Raw-аудит выполнен до sanitizer на каждом seed.

## Передача владельцам

Контрактных ошибок в кандидате не найдено. Есть воспроизводимые возможности
для оптимизации, **не блокирующие корректность**:

- Коммит `f95a8e3`; команда `python evals/compare_agents.py ... --runs 10`
  выше; seed 0. По расчёту официального порядка кампаний повторно затрагиваются
  3 747 финальных контактов. Ожидание для эффективности — меньше платных
  дублей; фактически они расходуют охват/деньги без второго прироста. Передать
  владельцу `strategy/` Бауыржану для оценки, менять его код в T-05 нельзя.
- Тот же коммит/команда, seed 1, 3, 6 и 8: по 3 382 повторных финальных
  контакта. На seed 42 — 371. Частичная обрезка ресурсами или cap 5 000
  происходит автоматически по официальным правилам и отмечается **только
  предупреждением**; сама по себе не является нарушением контракта.
- Коммит `f95a8e3`, seed 2: net ARPU −282 662.44 при 20 пилотах, хотя
  остальные 9 seed положительны. Это реальный отрицательный mock-сценарий,
  не доказательство ошибки алгоритма и не предсказание hidden score.
