## Находки и риски

1. **Высокий риск качества стратегии: 25 убыточных прогонов из 100.** Код работает, но положительный средний результат не обеспечивает защиту от убытков. Кейс отдельно требует оценивать устойчивость. В [strategy/core.py:163–181](https://github.com/BAITC-Hacks/hack-6e2e5c8b-sapatech/blob/4272a0787248de1481fb6b45dfcbdecee1568ae4/strategy/core.py#L163) наблюдения одного канала переносятся на другие; [выбор пилота](https://github.com/BAITC-Hacks/hack-6e2e5c8b-sapatech/blob/4272a0787248de1481fb6b45dfcbdecee1568ae4/strategy/core.py#L202) исследует самый дешёвый канал. Это уже известный возможный источник ошибки оценки; причинность для всех 25 потерь не доказана. Направление дальнейшего исследования — проверка риска платных каналов и неопределённости на парных сценариях, без подгонки под отдельный seed. В этом аудите алгоритм не менялся.
2. **P2, документация запуска.** [README:9–14](https://github.com/BAITC-Hacks/hack-6e2e5c8b-sapatech/blob/4272a0787248de1481fb6b45dfcbdecee1568ae4/README.md#L9) описывает рабочие ветки участников как текущее состояние, хотя итог находится в main. Раздел установки не указывает Python >=3.11 и не даёт законченного старта с venv и установкой requirements. Исполнимость подтверждена вручную подготовленным окружением, но воспроизводимость строго по README слабее. Направление исправления — одна проверенная последовательность установки и запуска для main.
3. **Ограниченный охват надёжности.** Четыре контролируемых сбоя пережиты корректно, но это не доказательство восстановления при любом повреждении данных или постоянном отказе всех пилотов. Таймер кооперативный и не прерывает зависшую синхронную функцию; на штатном коде задержек близко к лимиту не наблюдалось.

## Воспроизведение

В отдельном снимке main на Python 3.11+ (в аудите 3.13.7):

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/prepare_case.py '/path/to/beeline_case_participants (1).zip'
.venv/bin/python -m unittest scripts.test_agent strategy.tests.test_core evals.test_contract_checks -v
.venv/bin/python local_eval.py
.venv/bin/python evals/check_agent.py --agent agent.py --package . --feedback-check
.venv/bin/python evals/compare_agents.py --baseline-agent agent_template.py --candidate-agent agent.py --package . --runs 100
```

В аудите установка выполнялась через uv pip install в новом venv; pip-эквивалент выше не был отдельным повторным тестом. Multi-seed запускал ту же функцию `evals.compare_agents.evaluate` блоками по 10 с сохранением прогресса. CLI compare_agents возвращает 1 из-за двух raw-ошибок baseline; это нельзя выдавать за ошибку командного агента. Для CSV использовался `evals/check_submission.py --package _official --agent agent.py --strategy strategy`, где `_official` создан штатной scripts.prepare_case.install только из файлов ZIP.
