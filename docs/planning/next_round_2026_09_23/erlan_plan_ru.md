# Ерлан: независимая проверка, README и демонстрация

Статус: план следующего этапа. Начать выполнение после выдачи координатором
новой задачи/revision; действующий CONTROL=stop этот документ не меняет.
Общий порядок и критерии: [README](README.md).

## Результат твоей работы

Жюри может запустить выбранную версию по README. Команда получает доказательство,
что новая стратегия лучше текущей по согласованным критериям, либо обоснованный отказ.

Модель: **GPT-6 Sol medium** для команд, тестов, README и отчётов. **Sol high**
только для сложной ошибки проверки/изоляции. **Luna medium** — форматирование уже
проверенных результатов, без самостоятельного вывода метрик и решения о приёмке.

Пути: `evals/`, `docs/evaluation/`, `README.md`, собственная карточка задачи.
Не менять `agent.py`, `strategy/`, официальный scorer и общий submission.csv.

## Шаг 1. Сделать проверку двух версий достоверной

Текущий baseline: `4272a0787248de1481fb6b45dfcbdecee1568ae4`.
В аудите: 75/100 прибыльных, средний net +315 844.67, худший −585 009.70,
raw-ошибок нет. Это ориентир; файлы аудита должен передать координатор.

В существующем compare_agents обе версии исполняются одним Python-процессом,
а strategy импортируется по общему имени. Для сравнения двух командных ревизий
это создаёт риск повторного использования первой strategy из sys.modules.
Кроме того, общий package_dir может затенять путь второй стратегии.
Прежнее сравнение template против единственной strategy не равно этому сценарию.

- Использовать отдельный процесс и отдельную копию официального пакета на каждую
  ревизию. Разрешено несколько seed в одном процессе одной ревизии.
- Записывать hash исходников, пути загруженных agent/strategy и версии зависимостей.
- Проверить изоляцию содержательным тестом: две заведомо разные тестовые стратегии
  должны загружаться из своих каталогов и давать разные ожидаемые ответы.
- Добавить возможность задать начальный seed или явный список; сейчас --runs
  начинает с нуля. Проверить, что указанный диапазон действительно исполнен.
- Сохранять net, расходы, контакты, число пилотов/кампаний, время, raw-ошибки,
  предупреждения и hash для каждого seed. Средние считать кодом.
- Отделять ошибки baseline от ошибок кандидата: старый template имеет два
  известных пустых финальных ответа; сам по себе exit=1 сравнивателя не указывает
  на ошибку новой версии команды.

## Шаг 2. Параллельно закончить README

1. Указать выбранный трек, задачу, реализованные компоненты и состояние main.
2. Указать Python >=3.11; проверенный вариант 3.13.7, точные requirements.
3. Дать цельную последовательность: получить официальный пакет → создать venv →
   установить зависимости → подготовить локальный пакет → local_eval → CSV.
   Выбрать один способ подготовки и проверить его; не оставлять набор несвязанных
   старых команд. На Windows помечать только реально проверенные команды.
4. Объяснить, что исходные данные выдаёт организатор и они не лежат в Git.
   Для runtime внешние API и GPU не требуются.
5. Описать полный путь profile/history → кандидаты → пилоты → обновление оценки →
   выбор кампаний → официальный CSV; разделить модели помощников и код агента.
6. Дать актуальные метрики, ограничения и объяснить, что mock не предсказывает judge.
7. После выбора версии обновить hash и числа. Не объявлять эксперимент победителем заранее.

## Шаг 3. Независимо принять или отклонить кандидат

- Получить один замороженный hash от Бауыржана через координатора.
- Проверить raw-ответ до sanitizer, ресурсы вместе с пилотами, обратную связь,
  необходимые регрессионные тесты и два CSV в собственных копиях.
- Выполнить baseline и кандидат на контрольном диапазоне из общего плана.
- Посчитать среднее, медиану, долю убытков, минимум и среднее худших 10/100.
- Применить заранее согласованные критерии, перечислить все отклонения.
- Если кандидат провалился, сообщить это и сохранить baseline; не исправлять
  чужую стратегию или менять пороги, чтобы получить успешный отчёт.

## Готово, когда

- Проверен чистый запуск по финальному README.
- Есть отчёт с точными hash, командой/списком seed, исходными агрегатами и вердиктом.
- Сравнение ревизий изолировано; подтверждена загрузка нужных модулей.
- Метрики и ограничения README совпадают с выбранной версией.
- Проведена репетиция демо: задача → пилоты → результат → ограничения за 5 минут.

Нурсултану передать hash своей ветки, отчёт, проверенные команды и найденные
дефекты с владельцами. Общий CSV и отправку на платформе делает он.
