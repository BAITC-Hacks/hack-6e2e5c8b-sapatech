# Следующий этап Beeline: план для трёх участников

Дата: 2026-09-23. Статус: предложение для следующего этапа, не активное задание.
Этот пакет не меняет CONTROL=stop, не запускает расписания и не разрешает сдачу.

## Цель

Довести документацию и сдачу до готовности, отдельно проверить не более двух
изменений стратегии, направленных на снижение убытков без ухудшения среднего net.
Сохранить текущую проверенную версию, если улучшение не подтверждено.

Исходный commit: `4272a0787248de1481fb6b45dfcbdecee1568ae4`.
[Фактический аудит](project_actual_audit_2026_09_23_ru.md): 35 тестов проходят;
100/100 прогонов завершены, 0 ошибок исходного контракта, 75 прибыльных и 25
убыточных; средний net +315 844.67, худший −585 009.70. CSV воспроизводится.
Все числа относятся к mock; скрытый балл неизвестен.

## Критерии принятия стратегии

Baseline следующего этапа — текущий агент команды, а не слабый официальный template.
Проверять один и тот же набор seed для обеих версий.

1. 0 падений, 0 raw-ошибок, соблюдены лимиты и время, обратная связь влияет на
   решения; пройдены соответствующие тесты и воспроизводимость CSV.
2. На seed 0–99 выбрать не более одного финального кандидата из максимум двух
   экспериментов. До запуска контроля зафиксировать его commit и критерии ниже.
3. Ерлан единожды проверяет baseline и зафиксированный кандидат на seed 100–199,
   если этот диапазон ещё не использовался командой. Иначе до любых измерений
   выбирается другой непересекающийся диапазон из 100 seed.
4. Предлагаемый консервативный порог: средний net не ниже baseline; убыточных
   прогонов строго меньше; средний net худших 10 прогонов не ниже baseline.
   Эти условия должны выполняться и на разработочном, и на контрольном наборе.
   Порог — командная политика принятия, не гарантия статистической значимости.
5. Нет убедительного результата, времени или чистой проверки — оставить исходную
   стратегию. Не ослаблять критерии после просмотра результатов.

После просмотра контрольного набора он перестаёт быть новым. Не перебирать
на нём варианты до победы и не обещать скрытый балл. В отчёте сохранять все
эксперименты, включая неудачные.

## Общие границы

- Контракт build_candidates / choose_pilot / select_campaigns и Agent.act сохранить.
- Официальные environment/scorer/data неизменны. Не читать закрытые эффекты,
  не зашивать seed или победившие тарифы.
- UI, Managed Agents, сервер, GPU и обязательный LLM runtime не входят в этот этап.
- Только Нурсултан интегрирует; окончательные README и evals принадлежат Ерлану,
  strategy — Бауыржану. Исправления на границе передаются владельцу.
- Передача: task/revision, исходный и итоговый hash, файлы, команды, фактические
  результаты, ограничения. Не передавать «у меня работает» без hash.
- Работать от актуальной согласованной базы в отдельных ветках/каталогах;
  не выполнять reset старых веток и не терять личное авторство.
- Номера новых задач/ветки назначит координатор после проверки существующих.
  Этот пакет не создаёт ветки и не возобновляет старые STOP-задачи.

## Что получает команда

Обновлённый README с чистым запуском; воспроизводимый отчёт сравнения;
принятая версия либо сохранённый baseline; CSV именно выбранной версии;
пятиминутная демонстрация; подтверждение отправки после действия оператора.
