## Как строим ядро

1. Сначала локальный baseline и замер, затем собственный список кандидатов.
2. История переходов задаёт prior, но не вероятность конверсии и не причинный uplift.
3. Исследуем разные сегменты/тарифы; не тратим все пилоты на похожие гипотезы.
4. Обновляем оценки по реальным ответам run_pilot; учитываем малый размер выборки.
5. Выбираем портфель по дополнительному net gain с overlap, ценой и остатками.
6. Все границы проверяем детерминированно, включая исходный список до sanitizer.

В пакете 23 441 клиент, 21 тариф и 14 823 исторических перехода. Исторические ID
не пересекаются с целевой аудиторией. Есть пропуски признаков и исходный ARPU <= 0.
Один контакт push бесплатен по деньгам, но тратит контактный лимит. Повторные
кампании оплачиваются, а эффект клиента засчитывается только один раз, лучший.
Пилотный observed_lift_ratio уже учитывает канал. Не умножать его эффект повторно.

## Проверяем перед сдачей

- Официальный local_eval проходит; исходных кампаний 1–10, нет отклонённых фильтров.
- Пилоты реально проведены и разные наблюдения способны изменить решения.
- Все расходы пилотов и финала учтены; ни один лимит не превышен.
- 10 seed: среднее, медиана, минимум, разброс net result, расходы и runtime.
- Одинаковый seed повторяется; два запуска make_submission дают одинаковый CSV.
- На локальных проверках стратегия лучше слабого template по набору seed либо
  в README честно описаны результаты и причины выбора стабильной версии.
- Запуск без API работает; runtime целевой <5 минут, абсолютный предел 10 минут.
- Каждый участник имеет свои коммиты; README описывает реальные, проверенные команды.
- Сданы артефакты и получено подтверждение платформы — коммит сам по себе не сдача.
